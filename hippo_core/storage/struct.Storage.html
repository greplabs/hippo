pub async fn upsert_memories_batch(&self, memories: &[Memory]) -> Result<()>

Insert-or-replace a batch of memories inside a SINGLE transaction.

upsert_memory runs each write as its own implicit WAL transaction, so indexing a batch of N files cost N commits (+ per-row fsync/checkpoint pressure). Wrapping the whole batch in one BEGIN … COMMIT turns that into a single commit — a large indexing throughput win — and makes the batch atomic (a failure rolls the whole batch back rather than leaving a partially-written index).

pub async fn store_embedding_with_qdrant( &self, memory_id: MemoryId, embedding: &[f32], model: &str, kind: &MemoryKind, ) -> Result<()>

Store an embedding durably, with a write-through to Qdrant.

Contract (fixed): SQLite is the durable source of truth — the embedding is ALWAYS written to SQLite. When Qdrant is available we additionally write it through to Qdrant for fast vector search.

The previous implementation stored the embedding in exactly one place (Qdrant when up, SQLite when down). If Qdrant availability flapped between writes, embeddings written while it was up became unreachable once it went down (and vice-versa), silently losing them. Always writing to SQLite guarantees durability regardless of Qdrant state; find_similar still prefers Qdrant and falls back to SQLite.

A Qdrant write-through failure is logged but does NOT fail the call, because the durable copy already succeeded.

pub async fn get_all_memories(&self) -> Result<Vec<Memory>>

Return EVERY memory in the index.

This path previously capped at LIMIT 5000, which silently presented a truncated view as complete — losing data for callers like export_index and find_duplicates past 5000 files. The cap is removed so the full-table iteration is actually complete. For bounded/UI access, use get_all_memories_paginated.
