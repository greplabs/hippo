Result reranking.

This is the second-stage precision pass of the “elite retrieval” pipeline. It runs AFTER Reciprocal Rank Fusion (RRF) merges the semantic and keyword arms, and BEFORE the final truncation to the caller’s limit:

semantic (Qdrant, chunk roll-up) ⨁ FTS5 BM25
    → reciprocal_rank_fusion            (first-stage recall / coarse order)
    → rerank_stage (this module)        (second-stage precision re-order)
    → truncate(limit)                   (final results)

First-stage fusion maximises recall cheaply: RRF is rank-based and scale-free, so it is good at getting the right documents into the candidate set, but its ordering ignores strong precision signals (an exact title hit is worth more than being ranked 3rd in both arms). The reranker re-scores a bounded window of top candidates using those signals and reorders them.

Two implementations share the Reranker trait seam:

  • HeuristicReranker — the DEFAULT. Zero new dependencies, fully offline and deterministic. It re-scores using signals already attached to each candidate (fused score, lexical title/filename/tag matches, phrase vs scattered-term matches, favorite, recency). This is a real precision win over raw RRF order with no extra infrastructure.
  • OnnxReranker — an OPTIONAL, feature-gated scaffold (see the bottom of this file) for a future cross-encoder model. It is NOT wired to a model and adds NO dependency to the default build.
